# Ontology — Mailbridge

> **Статус:** черновик v0.2 (2026-09-12)
> **Цель:** зафиксировать сущности и связи процессной памяти организации.
> **Принцип:** сначала онтология — потом код. Ни строчки кода, пока модель не устойчива.

## 0. Манифест

> Люди мыслят квитанциями. Квитанция — снятие показания с сигнала.
> Это не процесс, это метрика. Люди мыслят свершившимися фактами.
> Но если ты видишь процессы — ты можешь планировать и складывать факты
> так, как надо, а не наблюдать сложенный кем-то результат.
>
> Гонцу, принёсшему плохие вести, рубили голову.
> Это — мышление квитанциями. Мы строим то, что видит процесс.

Mailbridge — не таск-трекер и не почтовый клиент.
Mailbridge — **процессная память организации**: слой, который фиксирует
кто, что, когда, по какому поводу решил, что сделал, что из этого вышло,
и как это связано с другими решениями.

## 1. Система vs Реальность

**Это ключевая рамка.** Без неё всё остальное теряет смысл.

### Реальность
- **Связна.** Нет изолированных сущностей. Нет «артефакта вне процесса». Нет «факта без процесса».
- **Непрерывна.** Процессы разворачиваются во времени.
- **Необъятна.** Управленец не может держать её в голове целиком.
- **Первична.** Она есть — независимо от того, видим мы её или нет.

### Система
- **Моделирует реальность, но не равна ей.**
- **Приближается** к реальности — постепенно, через факты, связи, процессы.
- **Ограничена** вычислениями, памятью, восприятием пользователя.
- **Вторична.** Она — инструмент познания реальности.

### Что это значит
- **Система должна помогать видеть процессы**, а не требовать, чтобы пользователь уже их видел.
- **Система допускает «сирот»** (задачи без процесса, артефакты без процесса, факты без процесса) — потому что пользователь ещё не увидел связь.
- **Система постепенно раскрывает структуру** — «тайное становится явным».
- **Система — тренажёр процессного мышления**, а не только инструмент.

> **Система не заменяет управленца. Она помогает быть эффективнее.**
> Повышает качество управления.
> Когда ресурсов не хватает — качество управления компенсирует их отсутствие.
> И наоборот.

## 2. Роль системы: ПФУ 1–2

Система выполняет **первые два этапа Полной Функции Управления**:

### ПФУ-1. Выявление фактора среды
- Фиксация **входящего потока**: письма, сообщения, события.
- **Сырьё** — необработанные факты.
- Фактор, который «давит на психику» — то, что требует реакции.

### ПФУ-2. Стереотип распознавания
- **Осмысление** фактов: что это, к чему относится, что значит.
- **Складывание в процессы** или **отнесение к группе**.
- **Формирование стереотипа** — повторяющиеся паттерны распознаются автоматически.

### Что это даёт управленцу
- **Не разрозненные факты**, а **систематизированный процесс**.
- **Не квитанции**, а **картина**.
- **Основа для решений**: планировать, управлять, реагировать.

### Что это значит для системы
- Система **не «управляет»** — она **готовит почву для управления**.
- Система **не «решает»** — она **показывает**.
- Система **не «заменяет»** — она **усиливает**.

## 3. Сущности (узлы графа)

### 3.1. Процесс (Process)
Непрерывный сигнал, разворачивающийся во времени.
**Долгоживущая сущность.** Может содержать другие процессы (вложенность).

| Атрибут | Тип | Описание |
|---|---|---|
| id | PK | |
| title | string | Краткое название |
| description | text | Суть процесса |
| root_decision_id | FK → Decision? | Корень (если есть) |
| parent_process_id | FK → Process? | Вложенность |
| owner_id | FK → Person? | Может отсутствовать |
| priority | enum? | Может отсутствовать |
| state | enum | `active` / `paused` / `completed` / `cancelled` / `stalled` |
| started_at | timestamp | |
| closed_at | timestamp? | |
| created_at, updated_at | timestamp | |

**Связи:** содержит факты, порождает задачи, создаёт артефакты, включает людей, относится к объектам, вложен в другие процессы, связан с другими процессами.

**Принципы:**
- **Owner может отсутствовать** — это диагностика, а не баг.

- **Состояние `stalled`** — не «завис сам», а «кто-то его не двигает». Система подсвечивает.

## 5. Инварианты

1. **Факт первичен.** Задача — следствие.
2. **Процесс — долгоживущая сущность.** Задача — точка. Процесс — линия.
3. **Система ≠ Реальность.** Система приближается к реальности.
4. **Сироты — норма.** Задача / факт / артефакт без процесса — временное состояние.
5. **Процесс может быть без owner.** Это диагностика, не баг.
6. **Одно решение → много процессов.** Вложенность.
7. **Глубина иерархии — по уровню рассмотрения.**
8. **Всё имеет время.** Хронология — первоклассная сущность.
9. **Система — тренажёр процессного мышления.**
10. **Система не заменяет управленца. Она усиливает.**

## 6. Сироты и подсветка

### Что такое «сирота»
Сущность, которая **в реальности** принадлежит процессу, но **в системе** связь не установлена.

- Задача без процесса.
- Факт без процесса.
- Артефакт без процесса.
- Процесс без owner.
- Процесс без движения (`stalled`).

### Что делает система
- **Подсвечивает** сирот.
- **Предлагает** связь (через AI, кластеризацию, граф).
- **Помогает** пользователю увидеть процесс.
- **Не навязывает** — предлагает.

### Зачем
- **«Тайное становится явным».**
- **Управленец видит** скрытые связи.
- **Качество управления растёт** без роста ресурсов.

## 10. Философская рамка

> **Система ≠ Реальность.** Реальность — связна. Система — приближается.
> Задача системы — помогать видеть процессы, а не требовать, чтобы их уже видели.
>
> **Стандартный пользователь не умеет видеть процессы.** Это умение надо тренировать.

>
> **Бизнес — не структура.** Процессы складываются вопреки, а не по приказу.
> Персоны с опытом формируют связи. Формальные приказы — это уже устоявшиеся связи.
>
> **Система — это ПФУ-машина.** Фиксирует факты (ПФУ-1), распознаёт стереотипы (ПФУ-2),
> складывает в процессы. Управленец получает не разрозненные факты, а систематизированный процесс.
>
> **Процесс без owner — не баг, а диагностика.** Система подсвечивает зону риска.
>
> **«Завис» — не состояние процесса, а результат чьего-то бездействия.**
>
> **Глубина иерархии — по уровню рассмотрения управленца.** Система не навязывает.
>
> **Одно решение → много процессов.** Они вложены. Система схлопывает до одного.
>
> **Система не заменяет управленца. Она усиливает.**
> Когда ресурсов не хватает — качество управления компенсирует их отсутствие.
> И наоборот.
