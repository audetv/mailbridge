# ADR-0004: Философские документы — вне публичного git, в локальном контейнере

> **Статус:** принято (2026-09-13)

## Контекст

`docs/ontology.md`, `docs/ROADMAP.md`, `docs/positioning.md` и
`docs/archive/ontology/v0.{1,2,3}.md` — документы-«философия»: методология
ПФУ, маркетинговая обёртка, план развития на годы. Они:

- не документация кода (не API, не архитектура, не ADR-инварианты);
- содержат идеи, которые автор сознательно **не выносит в открытый доступ**
  (внутренние термины, конкурентная позиция, кейсы);
- не должны попадать в историю GitHub-репозитория (даже после удаления —
  `git log` их помнит).

Решение владельца (2026-09-13): эти 4 пути **удаляются из git mailbridge**,
а живут в **локальном git-контейнере** `/home/audetv/work/mailbridge`
(по стандарту контейнера `project-structure`, с исключением: контейнер
по проекту mailbridge заведён в git, локально, без remote).

## Решение

1. Из git-репозитория mailbridge удалены пути:
   `docs/ontology.md`, `docs/ROADMAP.md`, `docs/positioning.md`,
   `docs/archive/ontology/`.
2. В `.gitignore` репозитория заведены правила-страхования на эти пути —
   случайный `git add` не вернёт их в коммиты.
3. Канонические копии — в локальном контейнере
   `/home/audetv/work/mailbridge/docs/` (локальный git, нет remote).
4. Исторические копии v0.1–v0.3 остались в истории git mailbridge
   (невозможно очистить без force-rewrite). Это **принятый риск**:
   полный вынос из истории = отдельное решение владельца (сменой remote /
   переименованием репозитория), пока не требуется.

## Последствия

- **Плюсы:** документы не в истории нового GitHub; редактируются локально;
  не смешиваются с кодовой документацией; PR-flow mailbridge остаётся
  чистым.
- **Минусы:** история v0.1–v0.1.x в GitHub осталась (см. выше); два места
  хранения — нужен порядок (локальный контейнер = канон, reпо — только
  техническая docs/).
- **Ограничения:** все новые философские документы создаются ПРЯМО в
  контейнере `/home/audetv/work/mailbridge/docs/` — НЕ в репозитории.
