# Ontology — Mailbridge

> **Статус:** черновик v0.1 (2026-09-12)
> **Цель:** зафиксировать сущности и связи процессной памяти организации.
> **Принцип:** сначала онтология — потом код. Ни строчки кода, пока модель не устойчива.

## 0. Манифест

> Люди мыслят квитанциями.
> Если ты видишь процессы — ты можешь планировать и складывать факты так,
> как надо, а не наблюдать сложенный кем-то результат.

Mailbridge — не таск-трекер и не почтовый клиент.
Mailbridge — **процессная память организации**: слой, который фиксирует
кто, что, когда, по какому поводу решил, что сделал, что из этого вышло,
и как это связано с другими решениями.

## 1. Сущности (узлы графа)

### 1.1. Процесс (Process)
Непрерывный сигнал, разворачивающийся во времени.
Не «проект», не «задача». **Долгоживущая сущность.**

| Атрибут | Тип | Описание |
|---|---|---|
| id | PK | |
| title | string | Краткое название |
| description | text | Суть процесса |
| root_decision_id | FK → Decision | Корень процесса (решение) |
| state | enum | `active` / `paused` / `completed` / `cancelled` |
| started_at | timestamp | Когда начался |
| closed_at | timestamp? | Когда завершён |
| created_at, updated_at | timestamp | |

**Связи:** содержит факты, порождает задачи, создаёт артефакты, включает людей, относится к объектам, связан с другими процессами.

### 1.2. Факт / Квитанция (Fact)

| Атрибут | Тип | Описание |
|---|---|---|
| id | PK | |

| source_id | string | ID внутри источника (Message-ID и т.п.) |
| author_contact | string | Кто (email/имя) |
| author_name | string | |

| received_at | timestamp | Когда произошло |
| state | enum | `new` / `processed` / `archived` |
| meta | JSON | Source-специфичные данные |

**Связи:** принадлежит процессу, порождает задачи, создаёт/меняет артефакты, уточняет другие факты.

## 2. Связи (рёбра графа)

| Связь | От | К | Описание |
|---|---|---|---|
| `process_has_fact` | Process | Fact | Процесс содержит факт |
| `fact_spawns_task` | Fact | Task | Факт порождает задачу |
| `task_creates_artifact` | Task | Artifact | Задача создаёт артефакт |
| `process_creates_artifact` | Process | Artifact | Процесс создаёт артефакт (минуя задачу) |
| `process_involves_person` | Process | Person | Человек участвует в процессе |
| `task_assigned_to` | Task | Person | Задача назначена человеку |
| `fact_authored_by` | Fact | Person | Автор факта |
| `process_relates_to_object` | Process | Object | Процесс относится к объекту |
| `object_responsible_person` | Object | Person | Ответственный за объект |
| `fact_refines_fact` | Fact | Fact | Факт уточняет факт |
| `process_related_to_process` | Process | Process | Процессы связаны |
| `decision_roots_process` | Decision | Process | Решение — корень процесса |

## 3. Инварианты

1. **Факт первичен.** Задача — следствие. Не наоборот.
2. **Процесс — долгоживущая сущность.** Задача — точка. Процесс — линия.
3. **Артефакт имеет версию.** Документ эволюционирует.
4. **Связи — граф, не дерево.** Процессы пересекаются.
5. **Всё имеет время.** Хронология — первоклассная сущность.
6. **Всё имеет автора.** Нет «безавторских» фактов/решений.

## 4. Что это даёт

- Видеть **весь процесс**, а не отдельные задачи.
- Понимать **контекст** каждого факта.
- Планировать **следующие шаги** (а не наблюдать сложенное).
- Отвечать на вопросы **по процессу** («где мы сейчас?», «кто участвовал?», «что решено?»).
- Индексировать **всё** через Manticore и задавать вопросы на естественном языке.
