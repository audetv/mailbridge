> **Цель:** зафиксировать путь от текущего состояния до продукта.

## 0. Принципы

1. **МИП — компас, не продукт.** Продукт работает без знания онтологии.
2. **MVP важнее идеала.** Выйти через 3 месяца.
3. **Продажа — с первой версии.** Не «когда идеально».
4. **Каждая версия — рабочая.** Не «полуфабрикат».
5. **Метрика — результат, не фичи.**
6. **Не всё сразу.** RBAC, Postgres, полный граф — позже.
7. **Сначала — боль. Потом — красота.**
8. **Ритм:** выходные — разработка, неделя — тест. Не ломать процессы.

## 1. Метрика MVP (v0.5)

Что должно **работать**, чтобы ты сказал «это продукт»:

1. **Retain:** письмо приходит → AI извлекает факты → они видны в UI.
2. **Recall:** я нахожу нужное **по смыслу** за секунды.
3. **Процессы:** задачи **объединяются в процессы** (вручную или полуавтоматически).
4. **UI:** я ориентируюсь в потоке: что открыто, что закрыто, к какому процессу относится.
5. **Ответы/отчёты:** система даёт ответы на запросы в приемлемом виде.
6. **Личный результат:** я пользуюсь этим каждый день и **не могу без этого**.

**Формат ответов/отчётов — TBD.** Пока не знаю. Определится в процессе.

## 2. v0.5 — MVP (3 месяца)

> **Отправная точка:** уже есть рабочий конвейер — IMAP → extractor → AI (`ai/`, очередь, вердикты) → `tasks`/`task_comments`/`inbox_items`. Retain ниже — **расширение этого конвейера** (факты вместо одних вердиктов), не новая логистика.

**Цель:** рабочий продукт, который решает боль «не могу ориентироваться в потоке».

### 2.1. Retain (фундамент)

- [ ] Промпт для выявления фактов (селективность, консолидация, язык).
- [ ] JSON Schema (what/when/where/who/why; fact_kind; fact_type; entities; causal_relations).
- [ ] Журнал LLM-вызовов (`llm_requests`): вход/выход, токены, время.
- [ ] Очередь (доработать существующую).
- [ ] Абсолютные даты (конвертация относительных).
- [ ] Классификация: `world` / `experience` / `observation`.
- [ ] Сущности (plain strings).
- [ ] Причинность (causal_relations).
- [ ] Консолидация близких фактов (`proof_count`, `source_record_ids`).

### 2.2. Manticore (поиск)

- [ ] Развернуть Manticore 29.9+ локально.
- [ ] Индексация: `inbox_items`, `tasks`, `comments`, `facts`.
- [ ] Полнотекстовый поиск.
- [ ] Векторный поиск (auto-embeddings, чанкинг).
- [ ] Гибридный поиск.
- [ ] Базовый Conversational Search (поиск по смыслу, не чат).
- [ ] Интеграция с Go-бекендом.
- [ ] Интеграция с UI.

### 2.3. UI (ориентация)

- [ ] Поиск по смыслу (Manticore).
- [ ] Список фактов.
- [ ] Связи (простые).
- [ ] Фильтры: открытые/закрытые, по проекту, по человеку.
- [ ] Ориентация в потоке (что открыто, что в работе, что закрыто).
- [ ] Базовые отчёты (что вижу, что болит).

### 2.4. Процессы (самое сложное)

- [ ] Задача может быть **привязана** к процессу (вручную).
- [ ] Процесс может **содержать** задачи.
- [ ] Открытые и закрытые задачи видны **в контексте процесса**.
- [ ] Подсветка «сирот» (задачи без процесса).
- [ ] **Полуавтоматическое объединение:** AI предлагает процесс, пользователь подтверждает.
- [ ] **Кластеризация:** похожие задачи группируются.

### 2.5. Хранение

- [ ] SQLite (пока — не переходить на Postgres).
- [ ] Векторы — в Manticore (не в SQLite).
- [ ] Граф — в SQLite (базовый).

### 2.6. Что НЕ войдёт (отложено)

- RBAC.
- Postgres + pgvector.
- Полный граф (memory_links, entity_cooccurrences).
- MentalModel, KnowledgePage.
- Слои над записями.
- EntityCandidate (авто).
- Обучение системы.
- Различение факт/запись/интерпретация (в UI).

## 3. v0.6 — ПФУ-машина (6 месяцев)

- [ ] Выявление процессов (кластеризация, кандидаты).
- [ ] Выявление сущностей (EntityCandidate).

## 4. v0.7 — Различение (9 месяцев)

**Цель:** система помогает различать факты, записи, интерпретации.

- [ ] Интерпретации (полно): сущность, автор, тип, уверенность, конфликты.
- [ ] Слои над записями: `KnowledgePage`, `MentalModel`.
- [ ] Graph maintenance: отдельная очередь, консолидация, инвалидация.

## 5. v0.8 — Слои над записями (12 месяцев)

**Цель:** система становится умнее с каждым днём.

- [ ] Слои: `observation_history`, `mental_models`, `directives`.
- [ ] UI: граф связей, дашборды, мобильный интерфейс.
