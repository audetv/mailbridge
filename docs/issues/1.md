## Анализ: Календарные приглашения Exchange в теле письма

### Что это

Письмо от Outlook содержит календарное приглашение в формате `text/calendar` (iCalendar) **внутри multipart/alternative**, а не как вложение. Структура:

```
multipart/alternative
├── text/plain (пусто)
├── text/html (пусто — только пустой <p>)
└── text/calendar (base64-кодированный iCalendar с событием)
```

### Почему AI не увидел

1. `text/plain` — пустой (`quoted-printable` с пустым телом)
2. `text/html` — содержит только `<p>&nbsp;</p>` — пустой абзац
3. `text/calendar` — **не обрабатывается** экстрактором, просто игнорируется

AI получил пустой `body_text` → вердикт «информация, нет текста».

### Что нужно

Обнаруживать `text/calendar` части в письме и извлекать из них текст события — так же как мы делаем для `.ics` файлов.

### Где это в коде

`internal/extractor/extractor.go` — метод `Extract`. Сейчас обрабатывает:

```go
bodyText := e.cleaner.CleanBody(env.Text)
bodyHTML := e.cleaner.SanitizeHTML(env.HTML)
```

Но `env` из `enmime` имеет и другие части. Нужно проверить `env.OtherParts` или аналогичное поле для `text/calendar`.

### Как enmime обрабатывает календарь

`enmime` при парсинге multipart/alternative:
- `env.Text` — text/plain
- `env.HTML` — text/html
- `env.OtherParts` — все остальные части (включая text/calendar)

Нужно:
1. Найти `text/calendar` в `env.OtherParts`
2. Декодировать base64
3. Извлечь событие (SUMMARY, DTSTART, DTEND, DESCRIPTION, LOCATION, ORGANIZER)
4. Добавить текст события в `body_text`

### План

**Шаг 1:** В `Extractor.Extract` — найти `text/calendar` части

**Шаг 2:** Декодировать и извлечь события через существующий `extractICalText`

**Шаг 3:** Добавить текст события в `body_text`

**Шаг 4:** Тест с реальным письмом календаря

### Функция-помощник

Можно использовать `extractICalText` из `preprocessor`, но она принимает путь к файлу. Нужна версия, принимающая строку iCalendar.
