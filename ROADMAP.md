### Версия в UI
**Зачем/боль.** При визуальном чеке v0.26.0 (инцидент: устаревшая статика на 8081) было невозможно в браузере увидеть, какая сборка реально подана; версия читалась только через `mailbridge version` бинарника.
**Границы фичи.** `GET /api/version` (публичный, JSON `{version, commit, built}`) + отображение в шапке Dashboard: версия в строке, commit + time сборки в tooltip; `make run-dev` вшивает те же значения (ldflags) — commit виден и в dev. НЕ «проверка наличия новой версии»/уведомления — отдельная тема (если понадобится — новая идея).
**Решения (владелец, 2026-09-18):** 1) эндпоинт **публичный** (без JWT); 2) версия в строке, commit+built — в tooltip; 3) значения показывать **как есть** (в т.ч. `dev`/`none`) — это полезнее: в dev видно реальную сборку; 4) порядок — эта фича = следующая (v0.27.0), «Сегодня/спринты» — после неё. Версия не жёстко привязана к фиче — номер = свойство артефакта «шаг завершён».
**Статус:** **ВЫПУЩЕН (v0.27.0, 2026-09-18; тег → Release, бинарник `0.27.0 (commit: 800a62f)`)** — PR #60 → `main` (CI green). `GET /api/version` публичный + бейдж версии в шапке Dashboard (commit+built в tooltip); `make run-dev` вшивает ldflags. Тесты: `internal/web/version_test.go`, `frontend/tests/views/DashboardVersionBadge.spec.js`, e2e `version-header.spec.js`. Квитанция: `archive/PLAN.v0.27.md`.

### «Сегодня» / «План» (v0.28.0)
**Зачем/боль.** При 50+ задачах — ответ «что я делаю сегодня/завтра/на этой неделе»: фокусировка на пике, не копание по списку.
**Концептуальное ядро (решение владельца, 2026-09-19):** у задачи **две независимые даты** — `due_date` (обещание, срок исполнения; просрочка = нарушенное обещание) и **`scheduled_date` (план: когда я её делаю)**; сейчас из-за одной даты «кидаю на сегодня» = переписывание обещания ради организации дня.
**Решения (владелец, 2026-09-19, режим B):**
1. «Сегодня» = `scheduled_date = сегодня` **+ просроченные по due** (горящее — тоже видно в плане). «Намеренно совсем не видеть просроченные» — не делаем (крайний сценарий, отклонён).
2. Вкладки: статусные (Все/Активные/Бэклог/Выполненные/Закрытые) → **одна вкладка «Статус» + селект** (по смыслу — одна группа); **вкладка «План» — first-class** (селект «Сегодня/Завтра/Неделя»), состояние в URL (`?tab=...`), старое `?tab=active` и т.п. — **ломается** (закладок нет, один пользователь).
3. **Порядок вкладок: Инбокс, Статус, План, Проекты, Персоны** (по просьбе владельца — рабочие вкладки спереди).
**Границы фичи.** Поле `scheduled_date` + API-срез «План» (сегодня/завтра/неделя + просроченные due) + реорганизация вкладок + поле scheduled в UI (карточка/список). НЕ полноценные спринты (кандидат 3, риск «планировщик-дубль»), НЕ SLA/напоминания, НЕ «моё»/assignee, НЕ AI-извлечение scheduled (только руками). Планирование ≠ статус: статус задачи при «План» не меняется.
**Статус:** решения зафиксированы (в PLAN — детали шага v0.28.0); старт = новая сессия, режим A.
